## A. 用語↔問題リンクの作り方と信頼度

機械的な照合で作り、保守的に絞った。曖昧なものはリンクも付与もしていない。

1. **答えが用語そのもの**（正解の選択肢が用語の表記、または括弧内の別表記と一致、または「用語（補足）」形式）の問題を、その用語の `relatedQuestionIds` に追加。信頼度: 高。
2. **問題文が用語名で始まる**（3 文字以上）問題も `relatedQuestionIds` にだけ追加。例:「HTMLの説明として…」。信頼度: 中。問題文の途中に用語が出るだけのもの（例:「無線LANの通信を暗号化して…」）は誤リンクが多いため含めない。
3. `conceptId`（=termId）と `angle` を既存問題に付ける条件:
   - 正解がちょうど 1 つの用語に一致し、問題文に用語名が含まれず、事例を示す語（「ある…」「〜したい」「場合」等）がなく、「〜を何と呼ぶか／〜はどれか」で終わる短い説明文 → `reverse`（521 問）。
   - 問題文が用語名で始まり「〜の説明として適切／正しいものはどれか」 → `definition`。
   - 手作業で確認した 2 問: it_passport-0833（アンゾフの成長マトリクスの象限を答える → `definition`）、it_passport-0248（TCP と UDP のどちらか → `comparison`）。
   - 事例形式・複数用語に一致・用語が問題文に含まれるもの（49 問）は付与していない。
4. 用語 640 語のうち 32 語はリンクが 0 のまま（正解にも問題文の冒頭にも現れない）。無理には付けていない。

注意: 既存問題の約 9 割は「説明→用語」の逆引きで、`conceptId` 付与後は `concept-single-angle` の警告（観点が 1 種類）が出る。これは観点を増やす余地を示す警告で、検証は失敗しない（警告 489 件）。

## 観点（conceptId / angle）と AI 下書きタグ

- `conceptId`: 用語データの `termId`（例: `it_passport_term-0013`）。
- `angle`: `definition` / `scenario` / `comparison` / `reverse`。新しい問題タイプ（trueFalse / cloze / reverseLookup）は、アプリに UI が入るまで追加しない。
- `tags: ["ai-draft"]`: AI が下書きし、人（運営者・専門家）の事実確認が済んでいない問題。確認が済んだら人が外す。残っている間は、広告表現（「別の角度で」等）の根拠に数えない。
